# 学术化博客写作

把 CS 期刊论文的结构与论证逻辑用到本站 Hugo 技术博客，用于练学术表达。详细节写法见 [reference-sections.md](reference-sections.md)；方向变体见 [reference-variants.md](reference-variants.md)。

## 工作流程

1. **确认文章类型**：算法 / 系统 / 理论 / 机器学习 / 综述 / 通用。用户未指定时用通用骨架，再按内容微调。
2. **输出 Hugo 骨架**：沿用站内 front matter，填入下方模板；`tags` 对应关键词（3–8 个）。
3. **按推荐顺序起草**（勿按章节外观顺序硬写）：
   1. 核心方法 / 系统 / 理论
   2. 实验 / 评估 / 分析
   3. 引言与结论
   4. 相关工作
   5. 打磨摘要与标题
4. **套用变体**：按类型替换章节名与顺序（见 reference-variants.md）。
5. **成稿自检**（全部通过再交付）：
   - [ ] 无夸张词（novel、revolutionary、颠覆性等）
   - [ ] 摘要为五句式，无文献引用与图表
   - [ ] 引言含 3–5 条可验证贡献
   - [ ] 结论未引入新结果
   - [ ] 术语/符号全文一致
   - [ ] front matter `description` 与摘要结论句一致

## 期刊 → 博客映射

| 期刊 | 博客 |
|------|------|
| 摘要 150–250 词 | 正文「摘要」节 + `description` 一句总括 |
| 关键词 | `tags` |
| 作者与单位 / 致谢 | 默认省略 |
| 参考文献格式 | Markdown 列表 + 链接；优先近五年权威来源 |

## 默认骨架（通用）

```markdown
---
title: ...
date: YYYY-MM-DD
draft: true
description: ...
categories:
  - ...
tags:
  - ...
---

## 摘要

## 1. 引言

## 2. 相关工作

## 3. 预备知识与问题定义

## 4. 方法 / 系统 / 理论

## 5. 实验 / 评估 / 分析

## 6. 讨论

## 7. 结论与未来工作

## 参考文献
```

## 改写已有草稿时

1. 识别现有结构缺哪几节，只补缺、不强行灌水。
2. 把散乱经历改写成「不足 → 做法 → 证据 → 局限」。
3. 抽出可验证贡献列表放进引言；摘要按五句式重写。
4. 统一术语，删掉夸张与口号式句子。
