# 各节详细写法

写作时按需查阅本节；与 SKILL.md 骨架配合使用。

## 标题

- **写什么**：准确反映研究内容。
- **常见模式**：方法名 + 问题 + 效果；系统名 + 应用场景；理论问题 + 主要结论。
- **不写**：夸张词（novel、revolutionary、颠覆性等）。
- **检查**：去掉品牌词后仍能看出研究问题与贡献类型。

## 摘要

- **篇幅**：约 150–250 词（中文约 300–500 字）。
- **五句式**：
  1. 问题背景与重要性
  2. 现有方法不足
  3. 本文提出什么方法/系统/理论
  4. 关键技术或理论贡献
  5. 主要实验结果或理论结论（尽量量化）
- **不写**：文献引用、图表、未在正文展开的细节。
- **检查**：读者只读摘要能判断是否值得往下读；`description` 与第 5 句一致。

## 关键词（→ tags）

- 3–8 个：研究领域、方法、应用、评价指标。
- 用标准术语，便于检索。

## 1. 引言

逻辑链（按序）：

1. **研究背景**：问题为什么重要
2. **已有工作**：别人做了什么（点到为止，细节留给相关工作）
3. **不足与挑战**：现有局限
4. **本文思路**：打算怎么解决
5. **主要贡献**：项目符号 3–5 条，可验证
6. **文章组织**：各节安排（博客可简写为 2–3 句）

贡献写法示例：

- 提出了一种……方法，解决了……问题。
- 设计了……系统，实现了……功能。
- 证明了……定理，给出了……界。
- 在……数据集/场景上评估，相比基线提升了……。

**检查**：贡献条每条都能在后文找到对应展开。

## 2. 相关工作

- 独立成章；**按主题分类**，不按时间罗列。
- 每类：代表方法 → 核心思想 → 局限性。
- 章末总结：已有工作没解决什么，本文如何不同。
- 理论向文章可较短，侧重理论脉络。

**检查**：不是文献堆砌；每类都有与本文的对比锚点。

## 3. 预备知识与问题定义

目标：读者只看本节就能理解后续方法。

通用内容：

- 符号表（如有）
- 问题形式化定义
- 评价指标定义
- 必要假设与约束

方向差异：

- **算法**：问题定义、符号、形式化描述
- **系统**：背景技术、系统假设、负载模型
- **理论**：数学符号、定义、假设、引理

**检查**：后文首次出现的关键符号/指标已在本节定义。

## 4. 核心章节：方法 / 系统 / 理论 / 算法

通用要求：逻辑清晰、符号统一、图表自明、足够复现。

### 算法类

问题形式化 → 总体框架 → 各模块设计 → 伪代码 → 复杂度 → 正确性（如有）→ 参数与实现细节。

### 系统类

总体架构图 → 各组件 → 关键机制与协议 → 数据流/控制流 → 实现细节 → 工程挑战与方案。

### 理论类

主要定义与假设 → 主要定理及证明 → 引理与推论 → 证明思路概述 → 与已有结果比较 → 假设合理性。

### 机器学习类

问题定义 → 模型结构 → 损失函数 → 训练算法 → 理论分析（可选）→ 实现细节。

**检查**：他人能否据此复现关键步骤；无“魔法参数”未说明。

## 5. 实验 / 评估 / 分析

算法与系统文通常必须有评估；理论文可无实验，有则更强。

### 实验设置

- 数据集/场景：来源、规模、预处理
- 基线：选择理由
- 指标：定义与公式
- 实现：硬件、软件、超参数
- 重复次数与统计显著性（如适用）

### 结果类型

- 主实验 vs 基线
- 消融（验证模块贡献）
- 参数敏感性
- 鲁棒性
- 效率（时间/空间/通信）
- 可视化

### 结果讨论（可并入本节或第 6 节）

- 为什么有效；与已有研究对比；失败案例；局限性。

### 理论文的“评估”

与已有理论界比较；数值验证；反例；假设放松后的影响。

**检查**：设置可复现；每个主要 claim 有对应图表或数据支撑。

## 6. 讨论

- 主要发现；理论意义与实践意义
- 适用条件与局限性
- 伦理、公平、隐私、安全（如适用）
- 未来方向（可与结论合并）

有些文章把讨论并入实验或结论——博客允许合并，但局限必须出现。

## 7. 结论与未来工作

- 总结贡献，**不重复粘贴摘要**
- 强调创新点与局限
- 提出未来方向
- **不引入新结果**

## 参考文献

- Markdown 列表 + 链接即可
- 正文提及处与列表对应
- 优先近五年高水平会议/期刊/权威文档

## 附录（可选）

详细证明、额外实验、数据集说明、伪代码、超参数表——正文放不下再放附录或仓库链接。
